# 客户来访接待安排

## 何时使用
用户说"客户要来公司参观/来访/调研,帮我安排接待"、"出一份接待方案/接待议程"时。

## 输入(先收集,不齐不猜)
开工前从对话、`customers/<客户简称>/customer.json`、`profile.md`、最近的 `meetings/` 纪要中取:
1. **来访基本信息**:客户简称、来访日期与时段、来访人数。
2. **来访名单**:姓名、职务、角色(决策人/技术把关/使用方/内线)。已在 `customer.json → contacts` 的直接引用,新面孔标出来并提醒用户回填。
3. **来访目的**:参观考察 / 方案汇报 / 产品演示 / POC 验收 / 商务洽谈 / 高层互访 —— 目的决定议程重心。
4. **关联商机**:若对应 `projects/<客户简称>-<项目名>/`,读 `project.json` 的 `stage`,议程按阶段设计(方案期重演示与案例,商务期重报价与实施保障)。
5. **我方可出席人**:对接销售(`customer.json → sales`)、售前、产品/研发、领导。**用户没说的人不要替他排上**。
6. **公司可用资源**:会议室、展厅/参观点、班车与接送、餐叙安排。

上述任一项拿不到 → 在产出物中写 `【待补充】`,并在最后向用户集中列出待确认清单。**不要虚构客户来访人姓名职务、不要虚构公司没有的展厅/参观点、不要虚构领导出席。**

## 步骤
1. **定基调**:一句话写清本次来访的核心目标(我方想拿到什么:推进到下一阶段/建立高层信任/打消某个技术顾虑),后面所有安排都服务这个目标。
2. **排议程**:按时间轴逐段列 —— 时间段 | 环节 | 地点 | 我方主讲 | 时长 | 要点。
   - 常规骨架:迎接签到 → 开场与双方介绍 → 公司/产品介绍 → 参观动线 → 方案汇报或演示 → 交流答疑 → 小结与下一步 → 送别(视情况加餐叙)。
   - 留 10~15 分钟缓冲;总时长与客户行程(航班/高铁/返程)对齐,行程未知标【待补充】。
3. **设计参观动线**:按物理顺序串点(前台/形象墙 → 展厅 → 研发区 → 实验室/机房 → 会议室),每个点写:讲解人、停留时长、讲什么(**只讲本次目的相关的点**)、注意事项(是否涉密、能否拍照)。**只用公司真实存在的参观点**,用户没提供参观点清单就先问。
4. **排出席人分工**:每人一行 —— 姓名 | 角色 | 承担环节 | 具体职责(接机/主持/主讲/演示操作/记录/摄影/送别)。关键环节安排 A/B 角备份。销售负责客情与商务话题,售前负责技术与演示,涉及承诺的话题指定唯一出口人。
5. **列会议室与物料准备清单**(可打勾的 checklist,分三类):
   - **场地**:会议室名称与容量、投屏/线材/转接头、音视频与远程接入、桌牌(按来访名单逐人)、横幅/欢迎屏文案、茶水与餐饮、停车位与访客登记。
   - **物料**:公司介绍与方案 PPT(对应槽位交付物,注明文件路径)、演示环境与备用录屏、案例材料、样机/样品、伴手礼、纸质资料份数(=来访人数+我方人数)。
   - **人与流程**:前台与保安报备、访客名单报备、接送车辆与司机、网络访客账号、应急预案(设备故障→备用录屏;人员迟到→环节顺延规则)。
   每项带**责任人 + 截止时间**(默认来访前一天下班前完成),责任人未知留【待补充】。
6. **风险与话术提示**:列出本次可能被追问的敏感问题(价格、交期、定制范围、竞品对比)与建议口径;对外承诺一律标注"待商务确认"。
7. **写下一步**:来访后的跟进动作(纪要、材料补发、下次会议),给出建议负责人与时间,提醒用户确认后可同步为待办。

## 输出
- 主产出:`customers/<客户简称>/visits/YYYY-MM-DD-来访接待方案.md`(目录不存在则新建;日期用来访当天)。
- 若明确关联某商机,在 `projects/<客户简称>-<项目名>/` 下留一行索引指向上述文件,**不复制两份正文**。
- 文档结构固定:来访概览 → 核心目标 → 议程表 → 参观动线 → 出席人分工 → 准备清单(checklist) → 风险与话术提示 → 下一步 → 【待补充】清单。
- 议程、分工、清单一律用表格或 `- [ ]` 勾选项,可直接打印带进会议室。

## 输出规范 / 铁律
- **客户事实(来访人、职务、行程)与公司资源(会议室、参观点、人员)不得编造**;没有 = 【待补充】,不用"常见做法"填坑。
- 出席人只写用户确认过的人;想建议某人到场,写进"建议邀请"并注明待确认。
- 涉及范围、价格、SLA、交期的表述,统一加"待商务确认"。
- 事实与建议分开:判断、话术、预案归入"风险与话术提示"一节。
- 完成后只输出:文件路径 + 议程总时长与环节数 + 【待补充】项条数。

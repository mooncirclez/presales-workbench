# 会议纪要整理

> 这是一个示例技能,演示技能的写法。请按你自己的工作习惯修改,或删除后新建。

## 何时使用
用户给出录音转写、聊天记录、速记等原始材料,要求整理成会议纪要时。

## 步骤
1. 通读原始材料,确认:客户、日期、参会人(客户方/我方)。缺失的信息标【待补充】,不要猜。
2. 按固定结构输出到 `customers/<客户>/meetings/YYYY-MM-DD-<主题>.md`:
   - 要点(按主题分组,每条一句话)
   - 客户关注 / 异议(原话尽量保留)
   - 行动项:`- [ ] 事项 @负责人 截止日期`
3. 若纪要中出现关键人的态度、组织架构、KPI 信息,提醒用户(或经确认后)同步维护该客户的 `customer.json`。
4. 行动项若涉及我方承诺(报价、交期、功能),在条目后加"⚠️ 对外承诺,需确认"。

## 输出规范
- 不编造任何客户事实;判断与建议放在"备注"一节,与事实分开。
- 精炼:纪要正文控制在一屏内,细节引用原文附在末尾。
